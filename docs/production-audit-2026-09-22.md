# Production-аудит CredoMir — 22 сентября 2026

## Итог

Репозиторий `boooobly/creso-site`, исходная версия `f72d8b6`, ветка `codex/production-audit`. До изменений зафиксированы сборка, lint, TypeScript, тесты, npm audit, Lighthouse и реальные screenshots Chrome. После исправлений выполнен повторный аудит. Концепция, услуги, цены и данные компании сохранены. Изменения не означают автоматическую готовность инфраструктуры production: ниже перечислены открытые риски файлов и масштабирования.

Стек: Next.js App Router 15, React 18, TypeScript, Tailwind 3, Prisma/PostgreSQL, Contentful, Vercel Blob, SMTP/Telegram, Vitest. Проверены публичные маршруты, API, защита admin, схема и миграции БД, расчёты, outbox, загрузки, metadata и конфигурация сборки. Для исследования использованы Serena symbol overview/find symbol/references и текстовый поиск маршрутов, env, CSS и динамических связей. Архивные апрельские аудиты в `docs` описывают прежнее состояние; этот отчёт относится к сентябрьской проверке.

- **Metadata:** проверены title/description всех 21 публичных страниц, дублей не обнаружено. Next Metadata API сохранён; OG-изображение теперь существует; Twitter/OG используют общий набор данных.
- **Canonical:** одна очищенная origin; `www.credomir.com` нормализуется; tracking query не создаёт отдельный canonical. На работающем сайте read-only GET подтвердил http/www → https://credomir.com, trailing slash → 308 и корректный canonical.
- **Sitemap:** публичные коммерческие страницы присутствуют; служебные страницы исключены; фиктивные даты удалены.
- **Robots:** production sitemap доступен; preview исключён из индексации; admin login и 404 noindex. Проверка исходников и metadata дополняет HTTP crawl.
- **Structured data:** безопасная сериализация JSON-LD; LocalBusiness использует настройки компании; Service ссылается на тот же @id; существующие Breadcrumb/FAQ соответствуют содержимому. Не добавлялись выдуманные рейтинги, цены и отзывы.

- **Semantic HTML:** один H1, логичные секции, устранён вложенный main, labels/focus/dialog names. Языковых альтернатив нет, hreflang не нужен; искусственные pagination/manifest не добавлялись.

Коммерческие страницы охватывают существующие услуги: багет, печать, резку, термоперенос, кружки, стенды и наружную рекламу. ## Осталось

1. **P1-08 — надёжность вложений.** В `/api/leads` сохранение заявки и outbox текста надёжнее отправки самих файлов. При сбое Telegram metadata остаются, байты теряются. Нужны private object storage, запись attachment reference до подтверждения, outbox отправки и контролируемый срок хранения. Подмена на public upload ухудшила бы приватность; хранение десятков МБ base64 в JSON БД не является безопасным локальным исправлением.
2. **P1-09 — большие файлы на Vercel.** [Ограничение Function request body — 4.5 МБ](https://vercel.com/docs/functions/limitations). Нужны подписанный direct upload, серверная верификация owner/type/size, передача references либо подтверждённый другой backend. Простое увеличение лимита в route не отменяет ограничение платформы. В этом аудите исправлен отдельный UI/API mismatch, но предел платформы остаётся.
3. **P1-10 — private customer uploads.** Текущие public URLs используются в admin/order/PDF/Telegram. Нужны совместимая миграция, авторизованная выдача и private store; смена одного `access` сломала бы эти потоки. Секретов и доступа к рабочему Blob нет.
4. **P2-13 — distributed rate limit.** Для нескольких инстансов нужен атомарный общий store (существующий интерфейс синхронный, удалённый store потребует согласованной async-адаптации). In-memory fallback не заявлен как защита всего кластера.
5. **P3-02 — размер компонентов.** Безопасно отложено механическое дробление больших калькуляторов/handlers: выше приоритет сохранности клиентских файлов.

Не проверены реальные PostgreSQL migrations/transactions на рабочей БД, доставка SMTP/Telegram, подключённый Contentful и платежи с настоящими провайдерами: локальные credentials отсутствуют. Моки и чтение кода этого не заменяют. Каталог из публичной таблицы загружался (208 профилей); при отключённой БД использовались предусмотренные проектом fallback-настройки. Docker runtime daemon недоступен; проверен standalone Node runtime, но не заявлена успешная сборка/запуск Docker image. Field CWV/INP, реальные поисковые кабинеты и мониторинг ошибок требуют production-данных.
